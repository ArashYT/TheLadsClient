## ModSync (task 6)
- Invites and joins: cosmetics-server/social.py; Core\client\social (SocialState, HostSession, GuestSession, p2p\Mux).
- No mod list is exchanged: game.modsHash is always empty; the join gate checks only mc, loader and pack id/version (SocialState.java:644-680).
- Mux uses streams 0-1; the spec keeps 2+ for pack transfer (docs/superpowers/specs/2026-10-23-friends-p2p-design.md:54,64).
- Reuse: loadedMods() (v26_3 adapter\VanillaGameBridge26.java:588) and the launcher's ModpackPatchEngine.cs (allow-listed hosts, mandatory hashes).
- Mods cannot load into a running game: the guest must fetch (Modrinth/CurseForge by hash, else P2P on stream 2), then relaunch through the launcher and rejoin. Only hash-checked files, only after the guest accepts.
- Design (11-10, built in steps; code: Core\client\social\modsync):
  - Which mods: the profile's own jars (launcher inventory ownership "user", installed and enabled). The launcher writes them before every launch to `<gameDir>\.lads-mod-cache\modsync.json` ({v, mods: [id, name, version, file, size, sha1, sha512, source, url]}). It looks each jar up by hash (Modrinth sha1, CurseForge fingerprint: ContentCatalog, the CurseForge key lives in the launcher only) and caches the answer. Pack profiles and 1.8.9 (Forge) do not sync.
  - Host: presence `game.modsHash` = ModSyncList.hash (32 hex; "" = nothing to sync, or an old client). It serves its list and its listed jars on Mux stream 2, only when asked there.
  - Guest: the host's modsHash is empty or equal to its own: joins as before. Else, once the link is up and before the game connects: asks for the list on stream 2 (never to a host whose modsHash is empty: an old Mux ends the session on a stream-2 frame), then ModSyncList.missing and ModSyncSource.plan. SITE jars: https from cdn.modrinth.com or *.forgecdn.net only, no question. P2P jars: one "trust this host's mods?" question per host, then stream 2. Every file: size and sha512 (ModSyncHash); a site download that fails falls back to P2P.
  - Files go to `<gameDir>\lads-modsync\<hostUuid>\<ModSyncEntry.localName()>`. The guest's mods folder and settings are never touched.
  - Relaunch: the game writes `<gameDir>\lads-modsync.json` (host, files with size and sha512) and quits. The launcher checks every file again and starts the same profile with `-Dfabric.addMods=<that folder>` and `-Dlads.modsync.host=<uuid>`; the game then rejoins that host. A normal launch has neither argument, so the guest's own setup is back. Fabric loads the higher version when the guest has another version of a synced mod.
  - Steps: [x] list, diff, hash check, source choice + tests (ModSyncCoreTest). [x] Mux stream 2 (Mux.STREAMS = 3) + transfer: ModSyncWire (line protocol), ModSyncServer (host: only its listed jars, each at most twice), ModSyncClient (guest), ModSyncDownloader (site CDN, redirects checked); ModSyncTransferTest runs them over a real Mux pair. [x] launcher (Services\ModSyncService.cs, ModSyncServiceTests): WriteListAsync after the inventory snapshot in MainWindow.LaunchGame (Fabric profiles; site lookup at most 8 s, cached in modsync-sources.json), TakeRelaunch on game exit (ApplyModSyncRelaunch), AddJvmArguments. Loader 0.19.5 checked: fabric.addMods takes a folder (it splits on ';', so a game folder with ';' in its path is still to refuse). Modpack and Experiences launches do neither.
  - Game flow and rejoin (11-10, merged, unit-tested, not run in game). ModSyncFlow: the guest's sync; `shared(gameDir)` = the listed jars that are in mods\ with the listed size (host list, hash and what is served); trusted hosts in `lads-modsync\trusted.json`. SocialBridge.gameDir()/quitGame() on 1.20.1 and 26.3 (1.21.11 and 26.2 have no Friends code). Host: SocialState.gameInfo() fills modsHash; HostSession.serveMods per guest on stream 2. Guest: GuestSession.modSync runs before connectToLocal when SocialState.needsModSync (the host's modsHash is 32 hex and differs, plain Fabric profile, the launcher's list file exists: without it nothing would start the game again). Progress shows under "Connecting to ..." (connectingStatus); the trust question is the red ConfirmDialog on the Friends screen (FriendsScreenLogic.askTrust; 3 minutes without an answer = no). A sync that fails joins without the mods and says so (toast), as before ModSync. Restart-loop guard: a game started for that host with nothing new to fetch connects.
  - Rejoin: the host remembers "bye relaunch" for 10 minutes (SocialState.relaunching); when that friend's presence goes offline and comes back it sends the invite again (works for friends and invite scope). The restarted game (-Dlads.modsync.host) accepts that host's next invite once, without a toast.
  - Anti-ban: a game started with a host's mods leaves any server that is not the friend's world, singleplayer, LAN or one of ours at once, with a toast (SocialState.sample). It has logged in by then; a block before the connect needs a mixin per version and is still open.
  - Left: start 1.20.1 and 26.3 once, then a real invite between two PCs (host with one Modrinth mod and one jar that is on no site, guest without them): trust screen, restart through the launcher, automatic rejoin, the guest's own mods untouched on the next normal start. It needs two game PCs online with two accounts, and this launcher build on the guest's PC (the restart is the launcher's ApplyModSyncRelaunch). 11-10 14:15: the connectors of arash-pc, cyrax-pc and desktop-57kj0bp were offline; bsd is on but has 1.4 GB free RAM and no client.
