# The Lads Client 1.2.3

## Added
- Worlds, resource packs, shader packs and the multiplayer server list are shared by every client version and profile through the normal Minecraft folder: `%APPDATA%\.minecraft\saves`, `resourcepacks`, `shaderpacks` and `servers.dat`. Profile folders link to them (no administrator rights needed), and LadsCore reads and writes the shared server list directly, merging changes made by another running game.
- Home buttons for Worlds, Resource packs, Shader packs and Screenshots. The Gallery, resource-pack downloads and the server picker use the shared folders too.
- A complete mod inventory on the launcher Mods page and in the in-game Lads menu (Installed mods): installed and switched-off jars, pack mods waiting to download, mods not in the pack for this version (with the reason), LadsCore and its modules, embedded libraries under their parent, and Minecraft/Fabric/Java. Filters: All, Lads modules, Third-party, Enabled, Disabled, Libraries & dependencies, plus search and Reset filters.
- Every standalone mod, including pack mods and LadsCore, can be switched on or off from the launcher or in game. Choices are saved per profile, survive relaunches, repairs and updates, and dependencies are resolved before anything changes. While the game runs, changes are marked Restart required and applied before the next start.

## Changed
- Third-party jars use each release's original file name instead of `lads-<mod id>.jar`. Existing jars are renamed with identical bytes and the same on/off state.
- Existing profiles are migrated once. Profile worlds and packs move into the shared folders, and identical copies are kept as backups. Different items with the same name are kept side by side under a new name, and two worlds are never merged. Server lists are merged, and a report plus a notice list anything renamed or waiting.
- The "Isolate profile" option now only keeps a profile's game settings (options.txt, keybinds) separate. The old "Sync resource packs from global" setting is retired.
- Deleting from Files, Gallery or Mods asks first and uses the Recycle Bin. Windows warns before anything that cannot be recycled is deleted permanently.
- Browse, Add from file, Update and drag-and-drop never overwrite files and only replace mods you added yourself.

## Removed
- GoodMC: Old Combat & Blockhitting is no longer part of the 26.2 and 26.3 packs. The copy the launcher installed moves to `.lads-mod-cache\retired\goodmc\` in each profile, so it can be recovered. A copy you added yourself stays and is marked as removed from the pack. LadsCore's console-style swing (LegacySwing) is unchanged.
- GoodMC saved a no-cooldown attack speed into your player data. When you next open a singleplayer world or host a LAN world on 26.2/26.3 without GoodMC installed, LadsCore resets exactly that value to normal, so vanilla attack cooldown returns. Multiplayer servers are not changed, and GoodMC's config files are left in place.

## Fixed
- Mods that the launcher list hid (18 on a full 26.3 profile, including every jar whose metadata contains line breaks) are shown again, and the counts match the files in the Mods folder.
- Switching off LadsCore or a pack mod is no longer undone on the next launch.
- The Update buttons no longer re-enable switched-off mods or replace pack mods.
- The launcher server list reads the real server file instead of always showing nothing.
- Items with a hidden tooltip no longer crash 26.2/26.3 when Tooltips TXF adds lines (this was hidden while GoodMC was installed).
- The 26.3 title screen shows the correct Minecraft version.
- A new 1.21.1 profile no longer crashes on its first start: Sodium Extra is updated from 0.9.0 to 0.9.1 in the 1.21.1 pack.

## Updating
- Installed v1.2.1 and v1.2.2 launchers update automatically when Minecraft and sign-in are idle. EXE-only development copies need TheLadsClient-win-Setup.exe.
- The first start after updating migrates each profile in the background; profiles whose game is running are migrated at their next launch. Mods you switched off in 1.2.2 stay off.
- Accounts, settings and Microsoft sign-in are unchanged. See docs/SHARED_CONTENT_AND_MODS.md for details.

## Verification and known limitations
- Launcher tests: 341 passed. Core common tests: 435 run, with the same 2 pre-existing failures (HUD ArmorHUD hot path, mixin defaultRequire check).
- In-game runs used an isolated copy of the global folder:
  - 26.3 full run: 248 native feature checks, 50 HUD-editor checks and 18 shared-content checks, including a stale-copy server-list merge. It created a world, pack, shader pack and server.
  - 26.2 requested-features run: 25 checks and 50 HUD-editor checks. It listed the 26.3 world without opening it, and saw the pack, shader pack and server.
  - 1.21.11 and 1.21.1 runs: 18 shared-content checks each.
  - A switch-off/relaunch/switch-on cycle and a LadsCore-off run confirmed through Fabric's loaded-mod list that switched-off jars were not loaded, and the files returned byte-identical.
- Not verified at runtime: two different games saving the server list at the same moment, the Recycle Bin warning dialog, clicks in the launcher and in-game toggles (automated equivalents were used), migration of the real `%APPDATA%\.minecraft` folder, and the broader 26.2 feature suites (nametag, crosshair and render-scale checks remain unresolved from 1.2.2).
- 1.21.1 does not keep a newer server-list field (code-of-conduct acceptance), so newer versions may ask again after 1.21.1 saves the list. Essential's own server data stays per profile.
