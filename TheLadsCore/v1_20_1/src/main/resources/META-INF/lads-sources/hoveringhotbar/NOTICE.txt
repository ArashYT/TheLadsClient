Modified by The Lads: repackaged into Lads Core as com.thelads.core.v1_20_1.embedded.hoveringhotbar
(mixin config theladscore.v1_20_1.embedded.hoveringhotbar.mixins.json) without Puzzles Lib or Forge Config API Port:
the key and tick helpers are replaced by the Fabric API calls Puzzles Lib makes on Fabric, and a minimal reader keeps
using config/hoveringhotbar-client.toml (hotbar_offset, move_experience_above_bar). The selection-height mixin runs
before Core's SmoothHotbar redirect of the same call.

Ported to Minecraft 1.20.1 from the Lads 26.3 embedded copy. 26.3 moves the hotbar through Fabric's hud element and
status bar height registries; 1.20.1 has neither, so the same movement is done where 1.20.1 draws each part: the
hotbar, the experience bar (and, three pixels higher when move_experience_above_bar is on, its level number), the jump
bar, the health row and the mount health row are lifted by the offset with a matrix translation around the Gui method
that draws them, the held item name and the chat are raised by the offset, and the hotbar selection frame is drawn 24
instead of 22 pixels tall. The hotbar_gui_layers setting (gui layers of other mods that move with the hotbar) has no
equivalent in 1.20.1 and is not used; its line in a config file written by the original mod is left untouched. The
language file is the one generated from the mod's ModLanguageProvider; no upstream image assets are included. A QA
probe was added. Everything stands down while the original hoveringhotbar mod is installed (Fabric jar, or Forge jar
under Sinytra Connector).

The complete modified source files (MPL-2.0) are in META-INF/lads-sources/hoveringhotbar/v1_20_1 in this jar.
